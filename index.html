Experimental · WebAssembly

The existing Certificate mode uses local WASM zsign and stays in the browser. The new Apple Account mode preserves the same layout but opens the local Windows companion for Apple login, 2FA and provisioning. No Apple credentials are entered on the public website.

Certificate mode
Uses MIT-licensed Sylva Signer code and CDN-hosted WASM assets. The local signer build passed compilation, but I haven't verified it signing an IPA in your browser. Memory limitations can affect large IPAs on iPhone. Optional remote installation features may not work on our domain.

Apple Account sign-in · Windows 6.1 beta

The full Windows bundle includes a local Apple Account provisioning engine with login, two-factor verification, sign/save and sign/install. No manual .p12 required for this mode.

OmnaLocation · Apple Maps

Choose a test location

Use Apple Maps and GPX for testing. OmnaSign Desktop 5.2 can also attempt developer location simulation on a trusted, USB-connected iPhone. A website itself cannot control its USB developer services.

How this works

Apple Maps opens your coordinates. GPX can be loaded into Xcode to simulate a location while debugging an app you develop. The desktop feature uses Apple developer location simulation, which can affect Core Location readings on supported phones while active. It does not hide your IP, cellular or Wi-Fi location, and some apps can reject simulated readings.

Apple MapKit documentation

Get OmnaSign 5.1 for Windows location testing

Requires separately installed pymobiledevice3, Developer Mode, a trusted device connection, and compatible iOS services. Windows 5.2 keeps an active developer session until you press Clear; iOS 27 support is unverified.
